# Требования безопасности — CampusPass

| ID | Требование | Критерий приёмки | Связанные T / D |
| --- | --- | --- | --- |
| SR-01 | Изменять и публиковать карточку мероприятия может только организатор, указанный как его автор. | Организатор B отправляет запрос на редактирование или публикацию мероприятия, автором которого является организатор A: запрос отклоняется, поля мероприятия и его автор не меняются. Автор A выполняет то же действие успешно. |  |
| SR-02 | Список зарегистрированных участников доступен организатору только для мероприятий, автором которых он является. | Организатор B запрашивает список участников мероприятия организатора A: запрос отклоняется, список не возвращается (или возвращается пустой/ошибка без данных участников). Организатор A получает список участников своего мероприятия. |  |
| SR-03 | Участник может отменить только собственную регистрацию. | Участник B по известному ID отменяет регистрацию участника A: запрос отклоняется, регистрация A остаётся активной, число свободных мест не меняется. Участник A отменяет свою регистрацию успешно, место освобождается. |  |
| SR-04 | Регистрация на мероприятие создаётся только от имени фактически аутентифицированного пользователя; создать или отменить регистрацию от чужого имени нельзя, даже если в запросе передан другой ID пользователя. | Аутентифицированный участник A отправляет запрос регистрации с ID пользователя B в теле/параметрах: запрос отклоняется. Список регистраций B не меняется. |  |
| SR-05 | Число активных регистраций на мероприятие не должно превышать заданную вместимость даже при одновременных запросах. | Для мероприятия с одним свободным местом одновременно отправляются два запроса регистрации от разных участников: подтверждается ровно один, второй получает отказ с указанием отсутствия мест; итоговое число активных регистраций не превышает вместимость. |  |
| SR-06 | Для одного пользователя не может существовать более одной активной регистрации на одно и то же мероприятие. | Участник, уже имеющий активную регистрацию на мероприятие, повторно отправляет запрос регистрации на то же мероприятие: запрос отклоняется, число его активных регистраций на это мероприятие остаётся равным одной, число занятых мест не увеличивается. |  |
| SR-07 | Мероприятие в состоянии `draft` не должно быть доступно для просмотра посетителям/участникам и недоступно для регистрации. | Посетитель или участник запрашивает мероприятие в состоянии `draft` (по прямому ID или в общем списке): мероприятие не возвращается в общем списке и/или запрос на просмотр/регистрацию отклоняется. После публикации то же мероприятие становится доступным. |  |
