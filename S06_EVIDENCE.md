# S06. Цепочка подтверждения свойств CampusPass

## Свойство и связь с моделью

- Цепочка T-07 → SR-07 → D-05 требует скрывать мероприятия в состоянии draft от общего списка.
- EventsController.GetPublished применяет фильтр State == Published на сервере до формирования ответа.
- Дополнительный инвариант предметной области из PROJECT.md: новое мероприятие имеет непустое название, положительную вместимость и будущую дату.
- Фабрика Event.Create проверяет эти значения до создания сущности. Начальное демонстрационное мероприятие теперь создаётся через ту же фабрику.

## Версия и условия

- Среда: .NET SDK 10.
- Тестовый проект: tests/CampusPass.Api.Tests.
- Команда: dotnet test tests/CampusPass.Api.Tests/CampusPass.Api.Tests.csproj.
- Проверки используют фиксированное время, поэтому результат не зависит от момента запуска.
- Машиночитаемый результат: [TestResults/campuspass-s06-tests.trx](TestResults/campuspass-s06-tests.trx).

## Проверки и результаты

- Негативная проверка SR-07 сохраняет опубликованное мероприятие и черновик, затем вызывает контроллер. Ответ содержит только опубликованную запись.
- Негативная проверка валидации передаёт вместимость 0 и -1. Оба варианта отклоняются до создания сущности.
- Негативная проверка передаёт время начала, равное текущему. Фабрика отклоняет значение как не находящееся в будущем.
- Позитивная проверка передаёт будущую дату и вместимость 25. Создаётся черновик с нулевым числом регистраций.
- Полный прогон: 5 тестов пройдено, 0 пропущено, 0 завершилось ошибкой.

## Вывод и границы

Проверки подтверждают серверную фильтрацию черновиков в общем списке и инварианты новой сущности Event для кода, использующего Event.Create. Они не подтверждают просмотр по прямому ID, отказ при регистрации на черновик, авторизацию организатора, ограничения PostgreSQL и конкурентную регистрацию. Для этих свойств нужны отдельные реализации и проверки.
